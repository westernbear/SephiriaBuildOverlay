# Sephiria Build Overlay

Sephiria Wiki 빌드를 게임 안에서 검토하고, 목표 아티팩트·무기·나무 뿌리 선택을 한 동작씩 확인하는 Windows/BepInEx 5 모드입니다. SephPlanner의 코드, DLL, 프리셋 형식에 의존하지 않습니다.

## 안전 원칙

- 모드가 실행하는 선택·구매·리롤·이동·교환·회전은 매번 키보드 `F8` 또는 패드 확인 조합을 새로 눌러야 합니다. 한 입력은 한 요청만 보냅니다.
- 실행 직전에 로컬 플레이어, 런, 후보, 재화, 공유 주사위와 화면 revision을 다시 검사합니다.
- 게임 데이터를 직접 바꾸지 않고 정상 버튼/상호작용/인벤토리 요청 경로를 사용합니다.
- 해당 행동의 결과가 관찰되기 전에는 다음 요청을 보내지 않습니다. 상태 변경, 요청 거절, 5초 타임아웃 시 중단합니다. 현재 확인은 관찰 기반이며 명시적인 서버 ACK 훅은 아닙니다.
- 현재 게임 엔티티의 ID·한국어 이름·희귀도·카테고리 또는 무기 티어·부모가 내장 1.0.33 카탈로그와 다르면 해당 자동 행동만 비활성화합니다.
- 멀티플레이에서는 로컬 소유 플레이어의 인벤토리와 상태만 읽습니다.

## 설치

요구 사항은 Sephiria 1.0.33과 BepInEx 5입니다. [Releases](https://github.com/westernbear/SephiriaBuildOverlay/releases)에서 `SephiriaBuildOverlay-{버전}.zip`을 받은 뒤 **게임 루트 폴더에 그대로 압축 해제**합니다. ZIP 내부가 다음 구조이므로 별도로 DLL을 옮길 필요가 없습니다.

```text
Sephiria/
└─ BepInEx/
   └─ plugins/
      └─ SephiriaBuildOverlay/
         ├─ SephiriaBuildOverlay.Core.dll
         └─ SephiriaBuildOverlay.Plugin.dll
```

## 소스 빌드

.NET 8 SDK가 필요합니다. 공개 BepInEx/Unity 참조 패키지를 사용하므로 Sephiria 설치 경로나 게임 DLL은 빌드에 필요하지 않습니다. 게임 DLL과 에셋은 저장소와 배포물에 포함되지 않습니다.

```powershell
dotnet restore SephiriaBuildOverlay.sln
dotnet test SephiriaBuildOverlay.sln -c Release
.\tools\BuildRelease.ps1
```

스크립트는 바로 게임 루트에 붙여넣을 수 있는 `dist\SephiriaBuildOverlay-{버전}` 폴더와 같은 내용의 ZIP, SHA-256 파일을 만듭니다.

## CI와 릴리스

- `main` 브랜치 push와 pull request마다 Windows에서 복원, Release 빌드, 자동 테스트와 배포 ZIP 생성을 실행합니다.
- `v0.1.0` 같은 SemVer 태그를 push하면 테스트 및 패키징 후 ZIP과 SHA-256을 첨부한 GitHub Release가 자동 생성됩니다.

```powershell
git tag v0.1.0
git push origin v0.1.0
```

배포물에는 Core와 Plugin DLL만 포함됩니다. BepInEx, Harmony, Unity와 게임 DLL은 설치된 게임의 것을 사용합니다.

## 사용법

1. `F9`를 눌러 `https://(www.)sephiria.wiki/builds/{UUID}` 또는 원시 UUID를 붙여넣습니다. SephPlanner의 F6과 충돌하지 않도록 변경했고 기존 기본 F6 설정은 한 번만 F9로 이전합니다. 그 외 사용자 지정 키와 이전 완료 후의 변경은 보존합니다.
2. 모든 자유 형식 구역을 `필수`, `추천`, `제외`로 분류합니다. 항목마다 역할, 횟수, 우선순위와 카탈로그 slug를 고칠 수 있습니다.
3. `검토 완료 및 활성화`를 누릅니다. 필수 항목이 해석되지 않으면 활성화되지 않습니다.
4. `F7`로 안내를 켜거나 끕니다. 실제 아이템에 필수=금색, 추천=하늘색 프레임을 표시하며 어두운 외곽선·밝은 모서리·두꺼운 테두리로 강조합니다. 다음 행동은 민트색 이중 프레임과 작은 확인 키로 구분합니다. 목표 밖 아이템의 외형은 바꾸지 않습니다. 수량은 목표에 마우스를 올렸을 때만 표시하고 소비 비용/주사위 위험은 확인 전에 항상 표시합니다.
5. 제안된 행동 하나를 실행하려면 `F8`을 한 번 누릅니다.

인벤토리를 열면 보유 석판의 위치·허용 회전과 목표 아티팩트 배치를 함께 탐색합니다. 목표 슬롯에 반투명 고스트와 석판의 최종 각도를 표시합니다. `F8`은 제안된 이동/교환 또는 네이티브 방향 90° 회전 **한 번만** 실행합니다. 최종 배치까지 여러 입력이 필요하며, 요청 결과를 확인한 후에만 다음 단계가 표시됩니다. 더 나은 결과가 없거나 완료된 경우 일반 F8은 아무 동작도 하지 않습니다.

수동으로 회전하려면 `Shift`를 누른 채 석판 위에 커서를 놓고 수동 회전 프레임이 표시된 뒤 확인 키를 누릅니다. 이는 최적화가 아닌 명시적인 수동 회전입니다. 네이티브 회전 입력도 계속 사용할 수 있습니다.

### 패드 입력

게임의 활성 `Gamepad` / `Keyboard&Mouse` 입력 모드를 그대로 따라갑니다. 패드가 연결돼 있다는 이유만으로 전환하지 않습니다. 게임이 키보드 모드로 돌아오면 확인 안내도 F9/F7/F8로 돌아옵니다. 패드 모드에서도 키보드 단축키는 사용할 수 있습니다.

기본은 **View/Back 버튼을 누른 채** 방향키 **↑ 검토 창, ← 가이드 표시 전환, → 추천 동작 하나 확인**입니다. PlayStation/다른 패드는 실제 Input System 장치가 제공하는 Share/Select/− 등의 버튼 이름을 표시합니다. Steam Input이 Xbox 장치로 노출하면 Xbox 이름으로 표시됩니다. `[Gamepad] Modifier` 설정에서 `selectButton`(기본), `leftStickButton`, `rightStickButton` 중 변경할 수 있습니다.

- 게임의 로컬 `PlayerInput`에 연결된 패드 한 개만 읽습니다. 연결 해제·복수 패드로 모호한 연결·포커스 복귀·입력 모드/장치 변경 시 누르고 있던 버튼으로 행동을 시작하지 않습니다. 확인 방향키를 놓고 다시 눌러야 합니다.
- 검토 창은 방향키로 버튼을 이동하고, 화면에 표시된 남쪽 버튼(A/크로스 등)으로 확인·동쪽 버튼(B/서클 등)으로 닫습니다. 긴 목록 대신 구역/항목/목표/체크리스트를 페이지로 보여줍니다. URL/UUID와 매핑 slug는 클립보드 붙여넣기로 입력할 수 있고 직접 텍스트 입력은 키보드 모드를 사용합니다.
- 검토 창은 키보드·마우스·패드 모두에서 모달 입력을 소유합니다. 뒤쪽 게임 UI 클릭/스크롤/제출/취소와 인벤토리 회전·버리기 같은 원시 입력을 차단하고, 패널 밖 클릭도 소비합니다. 닫은 버튼/키가 모두 놓인 뒤 두 프레임까지 보호하고 포인터 캐시를 비워 클릭 관통을 막습니다. 이 분리 훅을 설치하지 못하면 검토 창을 열지 않습니다. 다른 모드가 자체 원시 입력을 읽는 경로까지 통제하지는 않습니다.
- 검토 창 밖에서는 네이티브 입력을 차단하지 않습니다. 게임/Steam에서 View와 방향키에 추가 행동을 재매핑했다면 겹치지 않는 Modifier를 고르세요. 공유 주사위 경고는 계속 경고 방식입니다.
- 아이템 목표 수량은 패드로 네이티브 아이템에 포커스를 둘 때 표시합니다. 배치/회전 최적화도 같은 패드 확인 조합으로 한 단계씩 수행합니다. 수동 회전은 게임의 패드 회전 입력을 사용하며, 마우스 Shift 회전은 키보드 모드에서만 안내합니다.

입력 방식은 Unity의 [PlayerInput 문서](https://docs.unity3d.com/Packages/com.unity.inputsystem@1.5/manual/PlayerInput.html)의 제어 모드/장치 연결 모델을 따르며, 게임/Input System DLL이나 버튼 이미지 자산을 배포하지 않습니다.

### 자동 배치의 범위

- 게임의 `StoneTablet.ParseQuery`를 메인 스레드에서 읽기 전용으로 호출합니다. 위치·회전별 효과 맵은 캐시하며 처음 준비할 때 약 3ms 단위로 나눕니다. Unity 객체는 백그라운드로 보내지 않습니다.
- 조건부 `ITEM`/`CHARM`/`PLACED`, 고정 각인, 레벨 증감·비활성·조건 무시·배율 및 인스턴스별 제단 강화 값을 반영합니다. 아티팩트의 가장자리/내부/이웃 조건도 검사합니다.
- 필수 활성화 → 필수 레벨 → 추천 활성화/레벨 → 이동·실제 정방향 회전 비용 순서입니다. 소유 인스턴스를 보존하므로 일반 카테고리 콤보 수량은 배치 중 일정합니다. 아티팩트 배치는 공통 슬롯을 대상으로 최소 비용 매칭합니다.
- **최대 6개 탐색 패스·6,000개 평가의 제한 탐색이며 전역 최적해를 보장하지 않습니다.** 현재보다 나은 결과만 제안합니다. 같은 입력에서 완료된 탐색은 결정적입니다.
- 예상한 F8 한 단계만 관찰되면 최종 계획을 유지합니다. 런/플레이어·아이템·효과/권한이 예상과 다르게 바뀌면 오래된 계산을 폐기합니다.
- 현재 네이티브 칸 효과를 정확히 재현하지 못하거나, 미지원 특수 아티팩트/배열 보너스·64칸 초과 보드인 경우 자동 배치를 중단합니다. 정상 게임 입력은 차단하지 않습니다.

기본 키는 BepInEx 설정 파일 `BepInEx\config\io.github.sephiria.build-overlay.cfg`에서 바꿀 수 있습니다. 버전 불일치는 같은 설정의 `AcceptVersionMismatch`를 명시적으로 켜야 활성화할 수 있습니다.

중간 런에서 활성화하면 현재 인벤토리 인스턴스를 최소 획득 횟수로 기록하고 `기록 불확실`로 표시합니다. 이후 보상 획득은 Harmony 관찰 지점에서 별도 횟수로 증가하며 제단 강화는 세지 않습니다. F9의 `획득횟수 보정` 탭에서 수동 보정할 수 있습니다. 명시적으로 활성화한 검토 결과는 재로딩/재시작 후 게임 바인딩을 다시 검증하여 복원합니다.

실제 인게임 글자는 게임이 사용하는 TextMeshPro `PIXEL_SMALL` 폰트 자산을 참조합니다. 폰트 파일을 복사하거나 배포하지 않습니다. F9 검토 창은 별도 IMGUI UI로, 사용할 수 있는 Galmuri 또는 시스템 한글 폰트를 사용합니다. 가이드 창을 상시 띄우지 않으며 프레임과 반투명 고스트는 마우스 입력을 가로채지 않습니다.

### 인챈트 우선순위

네이티브 인챈트 화면에서는 보유 목표 아티팩트 프레임에 `강화 1`, `강화 2` 순위를 표시하며 1순위는 보라색 이중 프레임으로 강조합니다. 필수 → 빌드 우선순위(작은 수 먼저) → 현재 효과 레벨 개선 가능 → 낮은 강화 횟수 순으로 정렬합니다. 추천 목표는 필수 다음이며 같은 아티팩트의 여러 인스턴스도 따로 표시합니다. 호버/패드 포커스로 이유를 볼 수 있습니다. 최대 강화 횟수 도달·레벨 0·상태 불명인 항목에는 순위를 부여하지 않습니다. 현재 셀 레벨이 최대여도 게임이 강화를 허용하면 후순위 후보로 남깁니다. 모든 조합의 DPS를 계산하는 순위는 아닙니다.

강화는 네이티브 게임 확인창에서 수동으로 수행합니다. 인챈트 모드에서는 배치 고스트와 F8 이동·회전 추천을 중단합니다. 강화 소비를 모드가 자동 실행하거나 획득 횟수로 세지 않습니다.

## 데이터와 네트워크

- 고정 API `https://www.sephiria.wiki/api/builds/{UUID}`만 호출하며 쿠키나 로그인 정보를 사용하지 않습니다.
- 요청 제한은 10초, 응답 제한은 2 MiB입니다.
- 성공 응답은 `%LOCALAPPDATA%\SephiriaBuildOverlay`에 원자적으로 저장됩니다. 오프라인 복구 시 캐시 사용 사실과 나이를 표시합니다.
- 목표 횟수는 중복 제거된 `artifact_values`가 아닌 `content[].items[]`에서 계산합니다.
- 내장 카탈로그는 아티팩트 276개, 무기 158개, 나무 뿌리 21개입니다. Wiki 테이블 ID는 게임 ID가 아니므로 `tools\GenerateCatalog.ps1` 결과를 그대로 배포하면 안 됩니다. 게임 1.0.33 메타데이터로 444개 ID를 연결했고, 미해결 11개는 실제 게임 ID와 충돌하지 않는 별도 키를 사용합니다. 연결된 ID라도 실행 시 전체 메타데이터 검증에 통과해야 자동 행동이 허용됩니다.

## 프로젝트 구조

- `SephiriaBuildOverlay.Core` (`netstandard2.1`): import/cache, review, catalog verification, run progress, recommendations, confirmed executor, deterministic tablet/artifact solvers.
- `SephiriaBuildOverlay.Plugin` (`netstandard2.1`): BepInEx config/GUI, local-player Unity snapshot, candidate outline, normal game request bridge, reward observation.
- `SephiriaBuildOverlay.Tests` (`net8.0`): URL/schema/cache, duplicate goals, review gate, progress, dice policy, action safety, placement solvers.

특성 배분, 의상, 콤보와 과일꼬치는 v1에서 체크리스트입니다. 영구 특성 포인트는 자동 소비하지 않습니다. 모달 검토 창과 닫는 입력의 보호 기간 외에는 네이티브 게임 입력을 차단하지 않습니다.

## 검증 범위

코어와 플러그인 Release 빌드, 카탈로그 무결성, 136개 자동 테스트가 통과했습니다. 이전 버전의 실제 싱글플레이 런에서 가져오기/분류 게이트, 아이템 선택창 프레임과 비용 경고, 게임 폰트, F7 숨김/복원, 비실행 슬롯 고스트, 재로딩 후 승인된 빌드 복원을 확인했습니다. 예제 빌드 매핑 47개 중 46개가 검증됐고 희귀도가 다른 `ice_snow`는 자동 행동을 허용하지 않습니다.

v0.1.5 패드 전환/연결 장치 제한/중복 입력/포커스/검토 탐색은 순수 입력 모델과 읽기 전용 API 모형 테스트로 검증했습니다. 실제 게임의 키보드 입력 모드/로컬 패드 0개/모달 훅 설치와 비실행 패드 검토 창 렌더링을 확인했습니다. 실제 패드가 없어 하드웨어 입력·Steam Input·패드 검토 조작·네이티브 UI 충돌은 실게임 미검증입니다.

v0.1.6은 패널의 전 입력 모달 보호, F9 이전, 인챈트 순위, 종료 작업 취소를 자동 테스트로 검증했습니다. 기존 종료 덤프에서 Unity의 접근성 정리 후 Input System 재접근을 확인해 조기 접근성 정리 우회책을 추가했습니다. 실제 타이틀 정상 종료 두 번은 종료 코드 0·새 덤프 0개였습니다. Computer Use는 사용하지 않았고 신규 모달/강화 표시의 실게임 상호작용 및 활성 런·외부 접근성 클라이언트가 붙은 원래 종료 조건은 미검증입니다.

실제 F8 입력으로 유료 리롤(공유 주사위 4→3), 필수 아티팩트 선택(실제 인스턴스 추가와 획득 기록 +1), 기존 아티팩트의 빈 슬롯 이동(동일 인스턴스 (0,0)→(5,0), 돈/주사위 불변)을 확인했습니다. 기존 유일 효과 아이템을 다른 아이템의 신규 획득으로 잘못 검사하던 이동 오류를 v0.1.2에서 수정했습니다.

v0.1.3에서는 실제 회전 가능한 '전이' 석판에 F8을 각각 한 번씩 입력해 180°→270°→0°→90°→180°로 순환하는 정상 요청과 결과를 확인했습니다. 칸별 효과가 방향에 맞게 바뀌고 마지막에 전체 효과가 복원됐으며 돈 500/주사위 1과 아이템 배치는 유지됐습니다. F7 숨김 및 회전 불가 석판에서는 F8이 추가 회전 요청을 보내지 않았습니다.

v0.1.4에서는 통합 최적화가 찾은 석판 1개·아티팩트 2개 이동을 실제 F8 세 번으로 수행해 추천 목표 합산 레벨 12→14를 확인했습니다. 회전이 필요한 상태에서는 솔버가 선택한 270°→0° 회전을 커서와 무관하게 F8 한 번으로 실행했습니다. 돈 500/주사위 1은 유지됐고 완료 후 일반 F8은 추가 요청을 보내지 않았습니다. 안정 인벤토리 구간은 해당 PC에서 약 144 FPS, 스냅샷 평균 약 1ms였습니다.

조건부/고정 각인/배율/점유 칸 교환/중복과 불가능 보드는 순수 모델 테스트로 검증했습니다. 실제 조건부·고정 각인·점유 칸 교환 런, 금전 구매, 지혜 10 병합의 실게임 관찰은 미검증입니다. 상점의 보상이 아닌 획득 카운트와 보상 포기/주사위 변환 연결도 후속 작업입니다. 멀티플레이 실게임은 사용자 요청에 따라 검증 범위에서 제외했습니다.

알려진 제한: 게임 재시작이 같은 런의 이전 체크포인트를 복원해도 모드의 획득 기록은 자동으로 되돌아가지 않습니다. 재시작 후 실제 진행과 차이가 있으면 F9 획득횟수 보정 탭에서 수정하세요. 중복 병합/아이템 버리기 때문에 현재 인스턴스 수만으로 과거 획득을 복원할 수 없어 임의로 기록을 삭제하지 않습니다.

디버깅 기록은 [docs/DEBUGGING.md](docs/DEBUGGING.md), 재시작 없는 개발 및 코드 기반 읽기 전용 검사는 [docs/FAST_TESTING.md](docs/FAST_TESTING.md)를 참고하세요.
