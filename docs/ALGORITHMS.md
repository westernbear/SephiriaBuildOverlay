# 배치·석판 합성 알고리즘

## 선택 근거

슬롯별 효과가 고정되어 있으면 아티팩트 배치는 직사각형 선형 할당 문제입니다. 단순 할당에는 전용 알고리즘이 적합하지만 석판의 ITEM/CHARM/PLACED 조건과 아티팩트 이웃 조건은 다른 아이템의 위치에 영향을 받으므로 할당만으로 전체 문제를 풀 수 없습니다. [OR-Tools 공식 설명](https://developers.google.com/optimization/assignment/linear_assignment)이 이 구분을 설명합니다.

v0.1.14는 다음을 결합합니다. 모든 상황에서 가장 빠르거나 전역 최적인 알고리즘이라는 뜻은 아닙니다.

- 작은 보드: 가능한 위치·회전을 모두 검사합니다. 후보 수의 보수적인 상한이 평가 예산 안에 들어갈 때만 실행합니다. 이 경로를 끝낸 결과만 `ProvenOptimal`로 표시합니다.
- 큰 보드: 정확한 정수 비용을 쓰는 직사각형 shortest augmenting path 매칭으로 아티팩트를 배치합니다. 빈 슬롯만큼 더미 행을 만들지 않습니다. [Crouse의 논문](https://doi.org/10.1109/TAES.2016.140952)과 같은 계열의 방법이며 [SciPy 공식 문서](https://docs.scipy.org/doc/scipy/reference/generated/scipy.optimize.linear_sum_assignment.html)도 직사각형 할당과 수정된 Jonker–Volgenant 방법을 설명합니다. SciPy 코드를 복사하거나 Python 런타임을 배포하지 않습니다.
- 조건부 석판: 위치·회전과 아티팩트 재매칭을 함께 평가합니다. 단독으로 이득이 없는 변화도 태블릿별 상위 4개 후보로 남기고, 전체 예산의 일부를 두 석판 조합에 사용합니다. 국소 최적점에서 후보를 바꾼 뒤 다시 개선하는 접근은 [Iterated Local Search](https://arxiv.org/abs/math/0102188)에서 다룹니다. 본 구현은 게임용 제한 탐색이며 논문의 알고리즘 전체를 그대로 구현한 것은 아닙니다.

기본 예산은 6,000회입니다. v0.1.21부터 **필수 활성 개수 → 필수 우선순위별 활성·레벨·특수 효과 → 추천 우선순위별 활성·레벨·특수 효과 → 음수 슬롯 페널티 → 빌드 콤보 → 이동·정방향 회전 비용** 순으로 비교합니다. 숫자가 낮을수록 높은 우선순위이며 같은 우선순위는 합산합니다. 핵심 아티팩트를 위해 전체 레벨 합이나 낮은 우선순위의 추천 활성 개수가 줄 수 있지만 필수 활성 개수는 희생하지 않습니다. 단순 가중합이 아니라 순서대로 비교하므로 낮은 우선순위 아이템 여러 개가 핵심 목표를 밀어내지 못합니다. 큰 보드의 매칭도 정확한 다중 자릿수 정수 비용으로 같은 우선순위를 사용합니다.

중복 목표 수량을 넘는 인스턴스는 활성화·레벨·특수 효과 점수를 더하지 않습니다. 큰 보드의 매칭 단계는 조건과 수량 제한을 근사하지만 최종 후보는 전체 보드 점수로 다시 검사합니다. 같은 우선순위의 효율과 이미 작동하는 특수 연결·보호 콤보 제약은 유지합니다. 기존 배치보다 나쁜 결과는 실행 목표로 반환하지 않습니다.

v0.1.16의 음수 페널티는 아이템 자체 인챈트를 제외한 칸 효과를 검사합니다. 조건 미충족으로 표시 레벨이 모두 0이거나 인챈트 때문에 두 칸의 레벨이 모두 충분해도 음수 칸보다 0 칸을 우선합니다. 이 순서는 실제 필수·추천 효과를 희생하지 않으며, 매칭 비용과 전체 보드 평가 모두에 적용됩니다. 현재 빌드에서 이동 가능한 목표 아티팩트만 이 항목에 포함합니다.

자동배치는 한 번의 확인으로 목표 배치를 고정하고, 네이티브 요청·확인·예상 배치 관찰을 차례로 반복합니다. 256단계 제한과 단계별 시간 제한이 있으며, 키 재입력·창 닫기·포커스 상실·소유권/런/빌드/효과 변경·거절 시 중단합니다. 배치 완료는 고정된 목표 좌표와 회전을 확인했을 때만 표시합니다. 창 밖 슬롯이나 지원하지 않는 효과는 완료로 처리하지 않습니다. F8 아티팩트 선택 성공 후에도 같은 흐름을 시작하며 추가 구매·리롤·강화·합성은 승인하지 않습니다.

석판 보상은 네이티브 instance ID로 쿼리·조건·회전 권한을 읽고 최대 12개 후보를 비교합니다. 현재 배치는 512회, 후보별 추가 배치는 1,024회 제한 탐색하며 현재 빌드 효과가 개선될 때만 선택을 추천합니다. 남은 빌드 아티팩트 선택이 먼저이고, 개선 석판 → 사용 가능한 무료/유료 리롤 → 네이티브 주사위 변환 순입니다. 리롤 뒤 종류가 바뀌면 기존 계산을 취소합니다. 빈 슬롯이 없거나 지원하지 않는 조건은 임의 석판 선택으로 우회하지 않습니다.

v0.1.21은 보상·상점 화면의 숨겨진 6,000회 고스트 탐색을 생략합니다. 석판 비교의 512/1,024회 예산은 줄이지 않았습니다. 쿼리 준비는 전체 합계 최대 3ms의 메인 스레드 프레임 슬라이스로 이어가고, 다른 석판과 번갈아 준비해도 진척을 버리지 않습니다. 완성된 효과 맵과 같은 탐색 내 동일 배치의 매칭 결과를 재사용합니다. 목표 우선순위·네이티브 효과 모델·화면 후보가 바뀌면 추천을 취소하고 다시 계산합니다. 단일 네이티브 파서 호출 자체가 3ms를 넘는 경우까지 강제로 중단하는 제한은 아닙니다.

CP-SAT도 검토했지만 v1에는 외부 솔버를 추가하지 않았습니다. 이 결정은 모드의 순수 C# 배포와 제한된 백그라운드 계산을 유지하기 위한 판단이며 CP-SAT보다 우수하다는 비교 결과는 아닙니다. [CP-SAT 공식 문서](https://developers.google.com/optimization/cp/cp_solver)는 최적·가능·시간 제한 상태를 구분합니다.

## v0.1.19 배치 효율 조사

[SephPlanner의 배치 솔버](https://github.com/nyabi-gh/SephPlanner/blob/3d62306d4815b0840d40483e343a98291f1b7e89/src/SephPlanner.Core/Solver/PlacementSolver.cs)를 비교했습니다. 석판 배치 빔의 부모별 몫으로 후보 다양성을 유지하고, 현재/이전 계획을 후보에 보존하며, 이웃 조건에 따라 재배정·재평가한 뒤 최선을 유지하는 구조입니다. 전체 코드나 평가값·프리셋을 가져오지 않았으며 런타임/배포 의존성도 추가하지 않았습니다.

우리 구현에서는 다음 두 손실을 수정 전 테스트로 재현하고 보완했습니다.

- **작은 가득 찬 보드의 정밀 탐색 누락:** 7개 아이템의 위치를 `7^7`로 계산했지만 서로 같은 칸에 놓을 수 없어 실제 배치는 `7! = 5,040`개입니다. 위치의 all-different 제약과 칸별 회전 수를 함께 반영하는 안전한 상한으로 바꿨습니다. 이 사례는 기본 6,000회 예산 안에서 5,040개를 전부 평가합니다. 고정 슬롯을 제외한 아티팩트 4개·제자리 회전 석판 2개는 `4! × 4² = 384`개로 확인했고, 383회 예산에서는 최적 증명을 표시하지 않습니다.
- **여러 석판의 동시 회전 누락:** 24칸이 가득 찬 합성 사례에서 석판 3개가 각각의 비활성 효과를 동시에 해제해야 목표가 켜집니다. 기존 단일 변화/두 석판 상위 4개 탐색은 활성 목표 0개에 멈췄습니다. 현재 위치에서 유효한 여러 석판 회전의 전체 조합이 남은 예산에 들어갈 때만 모두 평가하고 아티팩트 재매칭도 비교합니다. 같은 6,000회 한도에서 목표 활성화 0→1을 찾습니다. 새 회전 탐색을 완료해도 위치 전체의 전역 최적이라는 표시는 하지 않습니다.

이는 지금 사용자의 실제 가방이 전역 최적이라는 검증은 아닙니다. 현재 알고리즘에는 다음 제약이 남습니다.

- 큰 보드의 단일 매칭은 중복 수량 제한·이웃 조건을 근사합니다. 최종 점수에는 수량 상한과 전체 조건을 적용해 나쁜 후보를 거르지만 모든 더 좋은 후보를 찾는다는 보장은 없습니다.
- 여러 석판의 위치까지 한꺼번에 바꾸는 큰 조합은 전부 열거하지 않습니다. 회전 조합이 예산보다 크면 새 정밀 회전 경로도 생략합니다.
- 런타임은 빌드 밖/미검증 아티팩트를 고정합니다. 이 제약 때문에 좋은 칸을 전부 쓸 수 없는 경우가 있습니다. 보호 정책을 무시하거나 미지원 특수 효과를 임의로 점수화하지 않습니다.
- 최적이라는 표현은 **모드의 빌드 활성화·레벨·우선순위 점수와 고정 제약 기준**입니다. 실제 DPS/생존력이나 게임의 공식 전투력 최대화가 아닙니다.

공간 판정은 실제 타입별 네이티브 `GetEmptySlotCount(EItemType)`와 읽기 전용 `CanAddItem`을 사용합니다. 지혜 병합은 `uniquePairCount`, 같은 보유 인스턴스, `Enchant`와 `maxLevel`을 따로 확인하며 기존 유니크 연결 제한을 존중합니다. 균열은 네이티브 입구의 빈칸 검사 때문에 병합으로 공간 검사를 우회하지 않습니다. 받을 수 없는 목표는 빨간 프레임/공간 부족 표시로 보존하고 F8 실행은 요청 전에 중단합니다. 목표 후보가 없다면 네이티브 주사위 변환 확인 창은 유지하며, 공간 부족만으로 무의미한 리롤을 제안하지 않습니다. 버리기·판매·영구 재화 소비를 임의 실행하지 않습니다. 가득 찬 보드의 기존 교환/순환 교환 자동배치는 계속 지원합니다.

```powershell
dotnet test tests/SephiriaBuildOverlay.Tests/SephiriaBuildOverlay.Tests.csproj -c Release --filter 'FullyQualifiedName~BoardSearchRegressionTests|FullyQualifiedName~InventoryAdmissionTests'
./tools/dev/TestInventoryContracts.ps1
```

## v0.1.20 특수 아티팩트

[SephPlanner의 연결 보호·그룹 이동 구조](https://github.com/nyabi-gh/SephPlanner/blob/3d62306d4815b0840d40483e343a98291f1b7e89/src/SephPlanner.Core/Solver/DirectedCharmSupport.cs)를 참고하고 설치 게임 1.0.33의 동작을 읽기 전용으로 확인해 독립 구현했습니다. SephPlanner 코드·평가 가중치·카탈로그·프리셋을 복사하지 않았고 의존성도 추가하지 않았습니다.

- 북향의 침은 각 침의 실제 방향으로 연쇄를 따라 공격 가능한 최종 대상을 찾습니다. 비활성 중간 침도 통과하지만 순환·빈칸·비공격 아티팩트는 대상이 아닙니다. 게임의 레벨별 보너스·희귀도 추가 효과와 대상 분류를 반영합니다.
- 마나/재사용 보조 아티팩트는 각각 왼쪽/오른쪽 마법을 대상으로 계산합니다. 현재 작동하는 연결은 대상을 바꾸거나 비활성화하지 않습니다. 연결된 침·보조·대상을 하나의 구성 요소로 함께 옮기는 후보와 미연결 보조의 새 연결도 같은 6,000회 예산 안에서 검사합니다. 최종 배치는 기존 네이티브 교환 요청을 순서대로 확인합니다.
- 조화의 수정은 활성 여부와 별개인 이웃의 네이티브 표시 레벨, 상한, float 합산 순서와 내림을 반영합니다. 망원경은 PLANET 분류를 가진 실제 소환 행성만, 헌신의 휘장은 같은 행 전체의 동료만 계산합니다. 현재 활성 지원 대상은 연결을 유지합니다.
- 백지는 좌우 아티팩트에서 조건 수만큼 반복되는 분류를, 캘세더니 열쇠는 `Y % 분류 수`를 반영합니다. 침의 상속까지 계산하며 빌드에 지정된 콤보의 수량을 이동 비용보다 앞서 비교합니다. 콤보는 비활성 아티팩트도 셉니다. 과일·특성·지혜 병합 등 현재 수량의 고정분은 별도로 보존합니다.
- 대립의 천칭·영원의 식은 게임의 실제 경계인 `X <= 2`를 기준으로 현재 좌우를 유지합니다. 중간 교환에도 적용하므로 인벤토리 폭의 절반으로 잘못 판단하거나 다른 아이템에 밀려 반대편으로 옮겨지지 않습니다.

특수 효과 점수는 **네이티브 보너스 또는 지원 대상 수**입니다. 서로 다른 전투 효과를 완전한 DPS로 환산하지 않습니다. v0.1.21은 필수 활성 개수를 지킨 뒤 각 우선순위의 레벨·특수 효과를 확보합니다. 중복 획득 목표의 수량 상한도 그대로 적용됩니다. 마나 감소 점수는 100%에서 상한을 두며 실제 MP 비용/반올림/전투 빈도의 최적화라고 주장하지 않습니다.

## 합성 추천

합성 화면에서 로컬 인벤토리의 일반 석판만 검사합니다. 고정 각인, 합성된 커스텀 석판과 버릴 수 없는 아이템은 제외합니다. 게임의 읽기 전용 `CanMixTablet`으로 재료 회전과 조건의 호환성을 확인한 뒤, 효과 결합·공유 조건·회전 권한·빈 슬롯을 함께 평가합니다.

최대 16개 재료와 48개 네이티브 승인 회전 조합을 제한 탐색합니다. 합성 전 배치 개선 결과보다 빌드 점수가 낮아지는 조합은 추천하지 않습니다. 같은 효과라면 회전 권한을 잃지 않는 조합을 먼저 보여줍니다. 재료 프레임에 각도를, 합성 버튼 근처에 비용·재화 부족·회전 불가 경고를 표시합니다. 합성은 게임에서 직접 확인하며 모드가 선택·합성·소비 요청을 보내지 않습니다. 후속 배치까지 개선했을 때의 예상 효과이므로 합성 직후 같은 레벨이 보장되지는 않습니다.
