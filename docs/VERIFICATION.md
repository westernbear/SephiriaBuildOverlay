# 검증 범위와 제한

## v0.1.18

- 설치 게임의 과일 카테고리 ID 22개는 `ACADEMY`, `STURDY`, `DARKCLOUD` 등 대문자입니다. 코드 없는 빌드는 소문자 위키 slug/별칭을 만들었고 기존 ordinal 필터가 과일을 전부 제거했습니다. 수정 전 테스트에서 이 누락을 재현했습니다. 현재는 게임 카탈로그의 정확한 ID로 연결한 다음 중복·양/음 수량·적응형 보너스 슬롯과 용량을 검사합니다. 알 수 없거나 모호한 ID는 임의 연결하지 않습니다.
- 위키에 `fruit_skewer`가 명시되면 내장 프리셋 코드보다 우선합니다. 캐시된 예제 `724c6578-3343-41bd-a36d-4d5a71fe87b8`은 코드의 과일 8개와 위키의 6개가 달랐습니다. 구조화된 항목이 없으면 코드의 과일을 보존하고 빈 배열이면 비웁니다. 대소문자만 정확한 네이티브 표기로 바뀌는 것은 부분 실패로 알리지 않습니다.
- 무기도 구조화된 최종 목표가 있으면 검증된 부모 경로의 시작 무기를 다시 계산합니다. 최종 강화 무기를 로비에 지급하지 않습니다. 네이티브 프리셋은 기존처럼 `UpdateCurrentPlayer`의 정상 `EquipWeapon` 경로를 사용합니다. 이전에는 특성 응답만 확인했지만 현재는 저장된 선택값과 실제 `currentWeapon.entityId`, 과일 동기화 목록의 중복·부호·적응형 보너스까지 확인한 뒤 성공으로 처리합니다. 의상의 고정 무기는 존중하고 알립니다. 상태 변경·취소·시간 초과 시 기존 중단/복원 정책을 사용합니다.
- 자동 테스트 480개, Release 빌드 경고/오류 0개, 설치 DLL의 네이티브 API 18개와 무기·과일 응답 계약 검사 통과. Computer Use 없는 타이틀 검사 PID 34024에서 실제 과일 리소스의 정확한 ID 연결, 네이티브 UI/시작 카탈로그, v0.1.18 로드와 정상 종료 코드 0·새 덤프 0개를 확인했습니다. 타이틀에서는 초기화되지 않은 `ItemDatabase`를 호출하지 않고 네이티브 초기화가 사용하는 `ItemCategory` 리소스를 읽습니다. 로비의 실제 프리셋 적용이나 세이브·영구 자원 소비를 테스트로 수행하지 않았으므로 전체 로비 적용을 실게임 통과로 표시하지 않습니다.

## 이전 버전의 기록

코어와 플러그인 Release 빌드, 카탈로그 무결성, 136개 자동 테스트가 통과했습니다. 이전 버전의 실제 싱글플레이 런에서 가져오기/분류 게이트, 아이템 선택창 프레임과 비용 경고, 게임 폰트, F7 숨김/복원, 비실행 슬롯 고스트, 재로딩 후 승인된 빌드 복원을 확인했습니다. 예제 빌드 매핑 47개 중 46개가 검증됐고 희귀도가 다른 `ice_snow`는 자동 행동을 허용하지 않습니다.

v0.1.5 패드 전환/연결 장치 제한/중복 입력/포커스/검토 탐색은 순수 입력 모델과 읽기 전용 API 모형 테스트로 검증했습니다. 실제 게임의 키보드 입력 모드/로컬 패드 0개/모달 훅 설치와 비실행 패드 검토 창 렌더링을 확인했습니다. 실제 패드가 없어 하드웨어 입력·Steam Input·패드 검토 조작·네이티브 UI 충돌은 실게임 미검증입니다.

v0.1.6은 패널의 전 입력 모달 보호, F9 이전, 인챈트 순위, 종료 작업 취소를 자동 테스트로 검증했습니다. 기존 종료 덤프에서 Unity의 접근성 정리 후 Input System 재접근을 확인해 조기 접근성 정리 우회책을 추가했습니다. 실제 타이틀 정상 종료 두 번은 종료 코드 0·새 덤프 0개였습니다. Computer Use는 사용하지 않았고 신규 모달/강화 표시의 실게임 상호작용 및 활성 런·외부 접근성 클라이언트가 붙은 원래 종료 조건은 미검증입니다.

실제 F8 입력으로 유료 리롤(공유 주사위 4→3), 필수 아티팩트 선택(실제 인스턴스 추가와 획득 기록 +1), 기존 아티팩트의 빈 슬롯 이동(동일 인스턴스 (0,0)→(5,0), 돈/주사위 불변)을 확인했습니다. 기존 유일 효과 아이템을 다른 아이템의 신규 획득으로 잘못 검사하던 이동 오류를 v0.1.2에서 수정했습니다.

v0.1.3에서는 실제 회전 가능한 '전이' 석판에 F8을 각각 한 번씩 입력해 180°→270°→0°→90°→180°로 순환하는 정상 요청과 결과를 확인했습니다. 칸별 효과가 방향에 맞게 바뀌고 마지막에 전체 효과가 복원됐으며 돈 500/주사위 1과 아이템 배치는 유지됐습니다. F7 숨김 및 회전 불가 석판에서는 F8이 추가 회전 요청을 보내지 않았습니다.

v0.1.4에서는 통합 최적화가 찾은 석판 1개·아티팩트 2개 이동을 실제 F8 세 번으로 수행해 추천 목표 합산 레벨 12→14를 확인했습니다. 회전이 필요한 상태에서는 솔버가 선택한 270°→0° 회전을 커서와 무관하게 F8 한 번으로 실행했습니다. 돈 500/주사위 1은 유지됐고 완료 후 일반 F8은 추가 요청을 보내지 않았습니다. 안정 인벤토리 구간은 해당 PC에서 약 144 FPS, 스냅샷 평균 약 1ms였습니다.

조건부/고정 각인/배율/점유 칸 교환/중복과 불가능 보드는 순수 모델 테스트로 검증했습니다. 실제 조건부·고정 각인·점유 칸 교환 런, 금전 구매, 지혜 10 병합의 실게임 관찰은 미검증입니다. 상점의 보상이 아닌 획득 카운트와 보상 포기/주사위 변환 연결도 후속 작업입니다. 멀티플레이 실게임은 사용자 요청에 따라 검증 범위에서 제외했습니다.

알려진 제한: 게임 재시작이 같은 런의 이전 체크포인트를 복원해도 모드의 획득 기록은 자동으로 되돌아가지 않습니다. 재시작 후 실제 진행과 차이가 있으면 F9 획득횟수 보정 탭에서 수정하세요. 중복 병합/아이템 버리기 때문에 현재 인스턴스 수만으로 과거 획득을 복원할 수 없어 임의로 기록을 삭제하지 않습니다.
