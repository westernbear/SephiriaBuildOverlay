# 검증 범위와 제한

## v0.1.12

- 상세 패널은 IMGUI인데 커서는 uGUI에만 그려서 가려지던 경로를 수정했습니다. 기본 창에서는 기존 최상위 캔버스를 유지하고, 상세 창에서는 같은 게임 커서 스프라이트를 마지막 IMGUI 패스로 그립니다(커서 depth -1000, 창 -20). 회전/타이트 패킹 등 지원하지 않는 스프라이트는 시스템 포인터로 대체합니다. 닫기·포커스 상실·패드 전환 시 원본을 복원합니다.
- 로비에서 생략될 수 있는 `IsInDungeon` 키를 필수로 요구하던 조건을 수정했습니다. 값이 없을 때는 런 시작 플래그가 명시적으로 false이고 로컬 소유·바인딩된 세이브·단독 호스트가 확인되어야 허용합니다. 타이틀에서 가져온 빌드는 첫 안전한 로비를 기다리고, 로비에서 활성 빌드를 복원할 때도 한 번 적용합니다. 대기 중 던전 진입·소유권/세이브/런 변경·패널 준비 시간 초과는 취소합니다.
- Wiki `preset_code`가 없으면 구조화된 무기 경로·의상·일곱 특성·과일꼬치·아티팩트로 네이티브 프리셋을 생성합니다. `base`는 기지/ID 11이며, 과일 수량은 네이티브 ±1 항목으로 풀고 카테고리 별칭을 변환합니다. 명시된 시작 아티팩트 구역을 우선하며 없으면 원본 순서에서 해금·타입·용량 제한을 적용합니다. 영구 구매는 수행하지 않고 저장 프리셋 슬롯도 유지합니다.
- 자동 테스트 301개 통과, Release 빌드 경고/오류 0개. 새 34개 사례는 코드 없는 실제 빌드의 구조화된 필드, 전체 특성 메타데이터, 중복 주머니, 명시된 시작 구역, 없는 필드 유지, 손상된 과일 데이터, 로비 판정·일회 적용·상태 변경 취소와 커서 렌더링 표면/깊이 정책을 검사합니다. 설치 게임 DLL의 네이티브 API·해금 게이트·요청 큐 및 새 메타데이터 필드 계약은 읽기 전용으로 통과했습니다.
- 실제 1.0.33 타이틀/PID 12172에서 0.1.12 로드, 7개 특성 ID/한국어 이름/현지화 키 및 27종 의상 slug 매핑 일치, 실제 커서의 IMGUI용 스프라이트/UV 연결, 비활성 네이티브 UI 생성이 통과했습니다. 정상 네이티브 종료 코드 0, 새 덤프 0개입니다. Computer Use·던전 진입·자원 소비·세이브 수정은 하지 않았습니다.
- 실제 로비에서 세팅이 바뀌는 전체 경로와 상세 패널 위 커서의 픽셀 겹침은 이번에 실행하지 않았습니다. 위 메타데이터·순수 테스트·타이틀 검사를 그 실게임 통과로 표시하지 않습니다. 실제 패드 및 이전 행동 검증 제한도 유지합니다.

## v0.1.10

- Windows Computer Use 연결 후 v0.1.9 마을 화면에서 기본 창의 모든 글자 누락과 흰 입력칸을 재현했습니다. 새 화면 픽셀 캔버스에 원본 메뉴의 글자 배율·머티리얼과 선택 장식용 버튼 상태를 그대로 복사하던 코드를 제거했습니다. 게임의 Galmuri TMP 자산과 새 네이티브 입력/버튼 컴포넌트는 유지합니다.
- 원본 슬라이스 패널의 테두리가 작은 창의 콘텐츠와 겹치는 것을 실제 화면에서 확인했습니다. 스프라이트 PPU와 100 기준 캔버스의 환산으로 테두리를 최대 6px에 맞춥니다. 420×144 크기는 유지하며 버블도 같은 환산을 사용합니다.
- 설정 화면 글자 누락도 재현했습니다. 게임 로그에 설치되지 않은 Galmuri11의 폰트 로드 오류가 반복되고 있었습니다. 설치된 글꼴 목록에서만 선택하도록 바꾼 뒤 맑은 고딕으로 설정 글자가 보이고 같은 실행의 폰트 오류가 없는 것을 확인했습니다. 기본 창/버블은 실제 게임 TMP 폰트이며 설정의 대체 글꼴과 구분합니다.
- 커서는 게임의 실제 커서 스프라이트를 입력 없는 최상위 캔버스(32760)에 표시합니다. 원본 그룹을 숨기고 창 닫기/포커스/패드 전환 시 복원합니다. 리소스 누락 시 시스템 커서 대체와 이중 커서 방지는 순수 상태 테스트로 검사했습니다. 실제 기본/설정 패널 위의 커서 표시도 확인했습니다.
- uGUI의 빠른 드래그 이벤트 누락을 실제로 재현했습니다. 손잡이 내부의 왼쪽 마우스 다운으로만 시작하는 IMGUI 마우스 스트림을 추가해 게임 행동 없이 추적합니다. 최종 DLL에서 손잡이 드래그로 `PanelScale` 1→1.5, 닫기/재열기에서 크기 유지, 1.5→1 축소와 설정 파일 저장을 확인했습니다. 검증 후 원래 배율 1로 돌려놓았습니다.
- 최종 DLL/PID 30996에서 기본 패널 글자, 텍스트 입력, Enter의 잘못된 URL 거부와 왼쪽 하단 오류 버블, 설정/간단히 보기 전환을 확인했습니다. 모달 뒤 게임 시작 버튼을 눌러도 타이틀이 유지됐고 F9로 닫은 뒤 네이티브 종료 버튼은 정상 동작했습니다. 읽기 전용 종료 감시 결과 종료 코드 0, 해당 PID 덤프 없음, Player.log에 관리 종료 완료 및 Crash!!! 없음입니다.
- 219개 자동 테스트 통과, Plugin Release 빌드 경고/오류 0개. 새 순수 테스트는 작은 컨트롤의 폰트 크기, 슬라이스 PPU 환산/잘못된 값, 커서 레이어 순서, 실제 설치된 글꼴 선택과 한 번의 빠른 이동을 검사합니다.
- 이번 실화면 검증은 타이틀 UI에 한정합니다. 실제 패드, 던전에서의 원래 크래시 재현 조건, 시작 프리셋 적용 및 F8 소비는 새로 실행하지 않았습니다. 모드 자동 업데이트는 아직 미구현입니다.

## v0.1.9

- 기본 창에서 설명·통계·상시 상태·반복 키 안내를 제거했습니다. 게임의 실제 TMP 폰트와 슬라이스 스프라이트를 참조하고, 새 `UI_HorayButton`과 `TMP_InputField`에 모드 콜백만 연결합니다. 게임 DLL·에셋은 배포하지 않습니다. 세부 편집 화면은 IMGUI입니다.
- 알림은 입력을 받지 않는 하단 버블로 분리했습니다. 중복 억제, 제한 큐, 경고 보존, 포커스 상실 시 시간 정지, 만료·짧은 페이드·종료 정리를 테스트했습니다. 비용과 주사위 위험은 기존 아이템 안내에 유지합니다.
- 기본 Input System UI 맵이 정적 공유 객체인 것을 설치 DLL의 IL에서 확인했습니다. 모드 전용 맵을 새로 만들고, 보이는 모드 창의 모듈·액션 객체만 참조 동일성으로 허용합니다. 외부 액션·닫힌 창·이름이 같은 액션을 거부하는 순수 모델 테스트를 추가했습니다.
- 202개 자동 테스트 통과. 기본 패널은 420×144, 설정은 760×560으로 줄였습니다. 기본 창의 모서리 드래그는 전용 배율만 바꾸고 종료 시 설정에 저장합니다. 포인터 소유권, 비례 확대, 최소·최대/화면 경계, 전체 UI 배율과의 분리, 취소·잘못된 좌표를 테스트했습니다. 기본 컨트롤의 영역 경계와 겹침도 순수 좌표 테스트로 확인했습니다. 실제 입력, 화면 배치·커서 겹침·텍스트 잘림은 미검증입니다. Computer Use는 사용하지 않습니다. 타이틀 비활성 UI 생성 검사는 시각·입력 테스트를 대신하지 않습니다.
- 게임 타이틀에서 비활성 UI 생성 검사 통과: 실제 `Galmuri` 폰트, `MessageBoxBase` 패널, `UI_HorayButton`, `TMP_InputField`, 전용 입력 액션 8개, 드래그 이벤트 연결 3개와 네이티브 탐색 이벤트 차단을 확인했습니다. 모달을 열거나 게임 입력·가져오기·소비를 실행하지 않았습니다.
- v0.1.9 타이틀 정상 종료: PID 27264·11752·31608·33268, 모두 종료 코드 0, 새 덤프 0개. 최종 DLL에서도 UI 생성과 드래그 이벤트 연결을 확인했고 설치 DLL과 패키지 DLL 해시가 같습니다. 활성 런 종료·외부 접근성 연결 조건은 미검증입니다.

- 네이티브 API나 상태/소유권/버전/특성 적용 결과가 불명확하면 중단합니다.
- v0.1.7의 타이틀 정상 종료 회귀 검사: PID 33600, 종료 코드 0, 새 덤프 0개, 조기 접근성 정리 및 모드 종료 로그 확인. 런 중 종료나 외부 접근성 클라이언트가 붙은 조건까지 검증한 것은 아닙니다.

## 이전 버전의 기록

코어와 플러그인 Release 빌드, 카탈로그 무결성, 136개 자동 테스트가 통과했습니다. 이전 버전의 실제 싱글플레이 런에서 가져오기/분류 게이트, 아이템 선택창 프레임과 비용 경고, 게임 폰트, F7 숨김/복원, 비실행 슬롯 고스트, 재로딩 후 승인된 빌드 복원을 확인했습니다. 예제 빌드 매핑 47개 중 46개가 검증됐고 희귀도가 다른 `ice_snow`는 자동 행동을 허용하지 않습니다.

v0.1.5 패드 전환/연결 장치 제한/중복 입력/포커스/검토 탐색은 순수 입력 모델과 읽기 전용 API 모형 테스트로 검증했습니다. 실제 게임의 키보드 입력 모드/로컬 패드 0개/모달 훅 설치와 비실행 패드 검토 창 렌더링을 확인했습니다. 실제 패드가 없어 하드웨어 입력·Steam Input·패드 검토 조작·네이티브 UI 충돌은 실게임 미검증입니다.

v0.1.6은 패널의 전 입력 모달 보호, F9 이전, 인챈트 순위, 종료 작업 취소를 자동 테스트로 검증했습니다. 기존 종료 덤프에서 Unity의 접근성 정리 후 Input System 재접근을 확인해 조기 접근성 정리 우회책을 추가했습니다. 실제 타이틀 정상 종료 두 번은 종료 코드 0·새 덤프 0개였습니다. Computer Use는 사용하지 않았고 신규 모달/강화 표시의 실게임 상호작용 및 활성 런·외부 접근성 클라이언트가 붙은 원래 종료 조건은 미검증입니다.

실제 F8 입력으로 유료 리롤(공유 주사위 4→3), 필수 아티팩트 선택(실제 인스턴스 추가와 획득 기록 +1), 기존 아티팩트의 빈 슬롯 이동(동일 인스턴스 (0,0)→(5,0), 돈/주사위 불변)을 확인했습니다. 기존 유일 효과 아이템을 다른 아이템의 신규 획득으로 잘못 검사하던 이동 오류를 v0.1.2에서 수정했습니다.

v0.1.3에서는 실제 회전 가능한 '전이' 석판에 F8을 각각 한 번씩 입력해 180°→270°→0°→90°→180°로 순환하는 정상 요청과 결과를 확인했습니다. 칸별 효과가 방향에 맞게 바뀌고 마지막에 전체 효과가 복원됐으며 돈 500/주사위 1과 아이템 배치는 유지됐습니다. F7 숨김 및 회전 불가 석판에서는 F8이 추가 회전 요청을 보내지 않았습니다.

v0.1.4에서는 통합 최적화가 찾은 석판 1개·아티팩트 2개 이동을 실제 F8 세 번으로 수행해 추천 목표 합산 레벨 12→14를 확인했습니다. 회전이 필요한 상태에서는 솔버가 선택한 270°→0° 회전을 커서와 무관하게 F8 한 번으로 실행했습니다. 돈 500/주사위 1은 유지됐고 완료 후 일반 F8은 추가 요청을 보내지 않았습니다. 안정 인벤토리 구간은 해당 PC에서 약 144 FPS, 스냅샷 평균 약 1ms였습니다.

조건부/고정 각인/배율/점유 칸 교환/중복과 불가능 보드는 순수 모델 테스트로 검증했습니다. 실제 조건부·고정 각인·점유 칸 교환 런, 금전 구매, 지혜 10 병합의 실게임 관찰은 미검증입니다. 상점의 보상이 아닌 획득 카운트와 보상 포기/주사위 변환 연결도 후속 작업입니다. 멀티플레이 실게임은 사용자 요청에 따라 검증 범위에서 제외했습니다.

알려진 제한: 게임 재시작이 같은 런의 이전 체크포인트를 복원해도 모드의 획득 기록은 자동으로 되돌아가지 않습니다. 재시작 후 실제 진행과 차이가 있으면 F9 획득횟수 보정 탭에서 수정하세요. 중복 병합/아이템 버리기 때문에 현재 인스턴스 수만으로 과거 획득을 복원할 수 없어 임의로 기록을 삭제하지 않습니다.
